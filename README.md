# mOps

Кросс-платформенный плеер **YouTube Music** с интерфейсом **Material 3 Expressive**.
Один код на Linux, Windows, macOS, Android, iOS и Web — на Flutter.

> Неофициальный клиент. Не связан с Google LLC и YouTube.
> Не обходит технические средства защиты. Используйте в рамках условий сервиса.

## Что уже умеет

**Прослушивание**
- Поиск по YouTube Music: треки, альбомы, исполнители, плейлисты, видео
- Страницы альбомов, исполнителей и плейлистов
- Очередь воспроизведения с перетаскиванием, «следующим» и «в конец»
- Перемешивание, повтор (очереди / трека), авто-радио по треку
- Перемотка, громкость, скорость воспроизведения (0.75×–2×)
- Выбор качества звука (низкое / среднее / максимальное)

**Интерфейс**
- Material 3 Expressive: выразительная палитра, крупная типографика, пружинные переходы
- **Динамическая тема из обложки** играющего трека (или акцентный цвет на выбор)
- **Навигация и плеер — плавающие островки внизу**. Пока ничего не играет,
  остров навигации стоит один и скруглён полностью. С началом воспроизведения
  рядом встаёт островок плеера: они центрируются **общей группой**, между ними
  небольшой зазор, а на стыке скругление уменьшается до пары пунктов — пара
  читается как одна фигура. Очередь и текст растут вверх прямо из островка
- Островки накрывают содержимое, а не занимают место в раскладке, поэтому
  появление плеера ничего не сдвигает. Содержимое ограничено по ширине
  и центрируется — строки не растягиваются от края до края
- **Две раскладки**: узкая — обычная нижняя навигация и островок плеера над
  ней; широкая — остров навигации внизу рядом с плеером
- **Синхронизированный текст песни** с автопрокруткой и подсветкой строки
- **Масштаб интерфейса**: автоопределение DPI окружения либо ручной выбор

**Как устроен интерфейс**

Форма взята у ArchiveTune:

- треки в секциях идут **списком**, а карусель осталась только для альбомов,
  исполнителей и плейлистов — там важна обложка;
- строка трека: обложка, название и исполнитель двумя строками, справа
  длительность и меню действий;
- обложка играющего трека используется как размытый фон полноэкранного плеера;
- кнопки в шапке — круглые тональные, полоса перемотки тонкая, рядом отметка
  качества потока (`WEBM 147`);
- **все размеры заданы константами** (`lib/core/theme/layout.dart`): панели и
  карточки не меняют размер от текста и не «дёргаются» при изменении окна;
- **все иконки попадают в сборку**: иконки лежат в enum и кортежах, поэтому
  штатное «вырезание» неиспользуемых иконок удаляло их из шрифта — в
  запущенном приложении они рисовались пустыми квадратами. Сборка идёт с
  `--no-tree-shake-icons` (см. `packaging/install-desktop.sh` и `run.sh`).

**Аккаунт**
- Вход через Google (OAuth Device Flow) с автообновлением токена
- Либо вход по cookie браузера (SAPISIDHASH)
- Свои плейлисты, лайки, исполнители и подписки

**Доступ к сети**
- **Обход блокировок провайдера**: подмена хоста (domain fronting), прокси
  SOCKS5/HTTP, фрагментация TLS
- **Обход включён по умолчанию** — настраивать ничего не нужно
- **Поиск локального прокси для звука**: приложение само находит запущенный
  клиент (v2rayA, v2rayN, Clash, Tor…) и проверяет его настоящим подключением
- Кэш скачанных треков — повторное прослушивание играет без сети

```

  app.dart                      MaterialApp, тема, локализация
  core/
    audio/                      AudioEngine (интерфейс) + реализация на audioplayers
    auth/                       OAuth Device Flow, SAPISIDHASH, хранилище сессии
    innertube/                  клиент внутреннего API YouTube Music + обход ответов
    theme/                      Material 3 Expressive: схемы, формы, motion
    utils/                      форматирование длительности и чисел
  data/
    models/                     Track, Album, Artist, Playlist, Lyrics
    local/                      настройки
    sources/                    каталог, библиотека, парсеры, получение потока
  state/                        Riverpod: настройки, тема, плеер, авторизация
  features/
    home/ explore/ search/ library/ album/ artist/ playlist/
    player/                     панель плеера, полный экран, очередь, текст
    settings/                   настройки и аккаунт
  widgets/                      переиспользуемые компоненты
```

## Почему такие решения

| Вопрос | Решение | Причина |
|---|---|---|
| UI-фреймворк | Flutter | Material 3 Expressive поддерживается фреймворком, а не собирается вручную |
| Внутренний API | собственный InnerTube-клиент | один код-путь для гостевого и авторизованного доступа |
| Ссылки на поток | `youtube_explode_dart` | чистый Dart, без внешних бинарников вроде `yt-dlp` |
| Аудио | `audioplayers` | работает на всех платформах без системных зависимостей; на Linux — GStreamer |
| Состояние | Riverpod | кэш, состояния загрузки и ошибок из коробки |

Аудиодвижок спрятан за интерфейсом `AudioEngine`. Если понадобится gapless
и точный seek, реализация на `media_kit` подставляется в `lib/core/audio/`
без изменений в интерфейсе.

## Как запускать

### Обычное использование — ярлык в меню приложений

```bash
bash packaging/install-desktop.sh
```

Скрипт соберёт релизную версию, положит иконку и создаст ярлык. После этого
**mOps** появляется в меню приложений (в GNOME — по поиску в обзоре), как
любая другая программа. Повторять нужно только после изменения кода.

### Разработка — с горячей перезагрузкой

```bash
bash run.sh              # flutter run -d linux
bash run.sh release      # запуск собранной версии
```

`run.sh` сам подставляет Flutter в PATH: SDK лежит в `~/flutter/bin`, а его
там по умолчанию нет.

### Совсем напрямую

```bash
./build/linux/x64/release/bundle/mops
```

Бинарник работает из любого каталога — рядом с ним лежат его данные.

### Чтобы `flutter` работал в терминале

```bash
bash packaging/add-flutter-to-path.sh    # допишет путь в fish/bash/zsh
```

Скрипт ничего не перезаписывает: сначала проверяет, не добавлено ли уже.

## Сборка

Нужен Flutter 3.47+ (stable) и Dart 3.13+.

```bash
flutter pub get
flutter run -d linux      # или -d windows / -d macos / -d android
flutter build linux --release
```

### Зависимости для Linux

Приложение использует GStreamer (для `audioplayers`) и GTK3.
Проверить наличие:

```bash
pkg-config --exists gtk+-3.0 gstreamer-1.0 && echo OK
```

GStreamer должен уметь Opus и Matroska:

```bash
gst-inspect-1.0 opus matroskademux souphttpsrc
```

## Вход в аккаунт

**Самый простой путь — встроенный браузер** (Linux): Настройки → Аккаунт →
«Войти в браузере». Откроется настоящее окно входа Google на WebKitGTK; как
только вы войдёте, оно закроется само, а приложение заберёт cookie. Копировать
ничего не нужно.

Почему именно так: страницу входа Google нельзя пройти программно, а часть
нужных cookie помечена `HttpOnly` и из JavaScript недоступна. Поэтому окно
настоящее, а cookie забираются у менеджера cookie браузера.

Окно построено на системном WebKitGTK (`webkit2gtk-4.1`) — код лежит в
`linux/runner/webview_login.cc`. На других платформах кнопка не показывается.

Есть и два запасных пути — Google не выдаёт сторонним приложениям общие
OAuth-ключи, поэтому:

**OAuth (рекомендуется).** Создайте бесплатный OAuth-клиент:

1. `console.cloud.google.com` → новый проект
2. Включите **YouTube Data API v3**
3. OAuth consent screen → добавьте себя тестовым пользователем
4. Учётные данные → OAuth client ID → тип **TVs and Limited Input devices**
5. Вставьте `client_id` и `client_secret` в приложении

**Cookie.** Откройте `music.youtube.com`, скопируйте cookie `SAPISID`
(или `__Secure-3PAPISID`) и вставьте в приложении. Быстрее, но токен живёт меньше.

## Масштаб интерфейса (HiDPI)

Flutter на Linux работает через GTK3, а тот поддерживает только **целочисленный**
масштаб. Дробные значения (GNOME 125%, 150%) разные оконные системы обрабатывают
по-разному, поэтому приложение само определяет масштаб и компенсирует его.

Правило компенсации (см. `lib/state/ui_scale.dart`):

- **DPR движка меньше системного масштаба** — масштаб до приложения не дошёл
  (типично для GTK3 и дробных значений: 125% → DPR 1). Интерфейс увеличивается
  до системного значения. Это классический случай «мелкого» приложения.
- **DPR равен или больше системного** — оконная система уже масштабирует сама.
  Например, Mutter при 125% отдаёт DPR 2 и сам понижает кадр до 1.25.
  Вмешиваться нельзя: интерфейс стал бы в 1.6 раза мельче.
- **Автоматическое уменьшение не применяется никогда.**

Управление:

| Способ | Как |
|---|---|
| Настройки | Внешний вид → **Масштаб интерфейса** (Авто / 50–200%) |
| Клавиатура | `Ctrl +`, `Ctrl -`, `Ctrl 0` (авто) |
| Разово | `MOPS_UI_SCALE=1.25 ./build/linux/x64/release/bundle/mops` |

Поддерживаемые источники системного масштаба: `GDK_SCALE`, `GDK_DPI_SCALE`,
`QT_SCALE_FACTOR`, `QT_SCREEN_SCALE_FACTORS`, `~/.config/monitors.xml` (GNOME),
`~/.config/kdeglobals` (KDE). Из нескольких источников берётся максимум, а не
произведение: они описывают одно и то же разными способами.

Диагностика: debug-сборка при старте печатает строку `[DPI]` с системным
масштабом, DPR движка, размерами окна и итоговой компенсацией.

```bash
flutter run -d linux 2>&1 | grep '\[DPI\]'
# [DPI] система: ×1.25 (GNOME, масштаб монитора (1.25)); DPR движка: 2.0;
#       физический размер: 2560×1440; логический размер: 1280×720;
#       компенсация: ×1.000
```

## Почему звук требует обхода

В ArchiveTune звук работает без входа — но не потому, что там нет ограничений
YouTube. Их экстрактор (`rukamori/moriextractor`) **не извлекает поток сам**,
а обращается к серверу автора:

```
GET https://moriextractor.koyeb.app/api/extract?url=<ссылка>   (Authorization: Bearer …)
→ https://moriextractor.koyeb.app/api/play/<id>?sig=…&exp=…
```

Звук идёт **через этот сервер**, доступ по токену (у проекта есть админка
подписок). То есть за клиента всю работу делает чужая платная служба.

mOps извлекает поток сам, поэтому упирается в ограничение YouTube: сервер
отдаёт только первый ~1 МБ трека и отвечает 403 на остальное.

Проверено, что дело **не в клиенте и не в PO-токене**: я перебрал профили
из каталога Metrolist — Android VR 1.65.10 и iOS дают рабочие ссылки
(`c=ANDROID_VR`, `c=IOS`, без входа и без токена), но ограничение одинаково
у всех. Значит оно привязано к адресу, с которого приходит запрос: сервер
ArchiveTune размещён за границей, поэтому там ограничения нет.

Отсюда рабочие пути — прокси или VPN. Вход в аккаунт тоже помогает:
cookie передаются прямо в клиент получения потока.

В приложении теперь используются профили клиентов **Android VR 1.65.10**
и **iOS** (`lib/data/sources/youtube_clients.dart`) — они надёжнее клиента
по умолчанию, которому YouTube всё чаще требует PO-токен.

## Обход блокировок провайдера

Провайдер может обрывать соединение с YouTube по имени домена в TLS
рукопожатии (SNI). TCP при этом работает: рукопожатие к тому же IP с другим
именем проходит, а с `youtube.com` — нет. Диагностировать можно так:

```bash
# TCP проходит, а TLS — нет => блокировка по SNI
curl -s -o /dev/null -w '%{http_code}\n' https://music.youtube.com/     # 000
curl -s -o /dev/null -w '%{http_code}\n' https://www.google.com/        # 200
```

В приложении два механизма, которые включаются независимо.

### Подмена хоста (domain fronting)

Соединение идёт на разрешённый узел Google, а настоящее имя передаётся
в заголовке `Host`. Google обслуживает такой запрос как обычно. Побочный
бонус — обходится и фильтрация DNS: заблокированное имя вообще не нужно
разрешать.

| Что | Работает |
|---|---|
| Поиск, альбомы, исполнители, плейлисты | ✅ |
| Обложки, тексты песен | ✅ |
| **Аудиопоток** | ❌ |

Аудио так обойти нельзя: медиафайлы отдаёт отдельный сервер
(`*.googlevideo.com`), у которого собственный backend — через фронт-узел
Google запрос до него не доходит. Для звука нужен прокси или системный обход.

**Настраивать ничего не нужно.** Подмена хоста включена по умолчанию и
работает сразу: на незаблокированной сети она безвредна, а на заблокированной
без неё приложение не работает вовсе. При запуске приложение само проверяет
доступность и отключает подмену, только если она через этот узел не работает,
а прямой доступ есть.

### Прокси

SOCKS5 или HTTP-прокси. Даёт полную работоспособность, включая звук:
при включённом обходе аудио скачивает само приложение (где обход работает),
а затем проигрывает из кэша — GStreamer ходит в сеть напрямую и про обход
не знает.

### Звук

Медиафайлы отдаёт отдельный сервер (`*.googlevideo.com`). Здесь две разные
проблемы, и решаются они по-разному.

**1. Блокировка по имени домена.** Подменить хост медиасервера нельзя: у него
собственный backend, и запрос через фронт-узел Google возвращает `404`.
Поэтому медиахосты исключены из подмены, а канал прокладывает системный обход
(`zapret`, `GoodbyeDPI`, VPN) или прокси.

**2. Ограничение выдачи потока.** Даже когда соединение установлено, YouTube
может отдавать **только первые ~1 МБ трека**, а на остальное отвечать `403`.
Проверено на живом соединении: запросы в пределах первого мегабайта дают
`206`, за его границей — `403`. Это ограничение на стороне YouTube для
неавторизованных клиентов, а не блокировка провайдера.

Помогает:

- **вход в аккаунт** — приложение передаёт cookie или токен прямо в клиент
  получения потока, и условия выдачи меняются;
- **прокси или VPN** — меняют и путь, и условия выдачи.

Приложение ищет локальный прокси само:

Раздел **Настройки → Доступ к сети → Звук**:

- **Искать локальный прокси автоматически** (включено по умолчанию) — при
  запуске приложение перебирает порты известных клиентов и проверяет каждый
  настоящим подключением к медиасерверу, а не фактом «порт открыт».
  Найденный прокси включается сразу, подмена хоста при этом отключается.
- **Найти прокси сейчас** — та же проверка по кнопке, с отчётом о результате.

Проверяются порты: `20170/20171` (v2rayA), `10808/10809` (v2rayN),
`7890/7891/7897` (Clash), `2080` (Sing-box), `1080/1081`, `1087`, `8080`,
`8118`, `8888`, `3128`, `9050/9150` (Tor). Проверки идут параллельно,
поэтому поиск занимает около секунды.

Если прокси не найден:

- запустите клиент (v2rayA, v2rayN, Clash, Tor…) и нажмите **Найти прокси
  сейчас**;
- либо укажите прокси вручную в том же разделе;
- либо включите системный обход (zapret / GoodbyeDPI / VPN).

Скачанные треки остаются в кэше, поэтому повторное прослушивание играет
мгновенно и уже без сети.

### Диагностика

Пошаговая проверка всех звеньев — DNS, доступ к API напрямую и с подменой,
доступность медиасервера, поиск прокси, получение ссылки и скачивание:

```bash
dart run tool/diagnose.dart          # что где обрывается
dart run tool/download_probe.dart    # скачивание реального трека
```

### Фрагментация TLS

Первый пакет соединения дробится на мелкие части, чтобы имя домена не попало
в один сегмент. Помогает не везде: если оборудование провайдера собирает
TCP-поток обратно, приём не срабатывает. Проверено на живом соединении: узел
действительно дробит пакеты (есть тест), но конкретный DPI их пересобирает.
На сетях без пересборки фрагментация работает — поэтому она оставлена
как опция.

### Что выбрать

| Ситуация | Решение |
|---|---|
| Есть `zapret` / `GoodbyeDPI` / VPN | системный обход, в приложении ничего включать не нужно |
| Есть локальный прокси (v2rayA, v2rayN, Clash…) | приложение найдёт его само — заработает всё, включая звук |
| Есть внешний прокси | укажите вручную в разделе «Прокси» |
| Ничего нет | Подмена хоста: просмотр, поиск и тексты без ограничений, звук — нет |
