# mOps

Кросс-платформенный плеер **YouTube Music** с интерфейсом **Material 3 Expressive**.
Один код на Linux, Windows, macOS, Android, iOS и Web — на Flutter.

> Неофициальный клиент. Не связан с Google LLC и YouTube.
> Не обходит технические средства защиты. Используйте в рамках условий сервиса.

## Что уже умеет

**Прослушивание**
- Поиск по YouTube Music: треки, альбомы, исполнители, плейлисты, видео
- Страницы альбомов, исполнителей и плейлистов
- Очередь воспроизведения с перетаскиванием, «следующим» и «в конец»
- Перемешивание, повтор (очереди / трека), авто-радио по треку
- Перемотка, громкость, скорость воспроизведения (0.75×–2×)
- Выбор качества звука (низкое / среднее / максимальное)

**Интерфейс**
- Material 3 Expressive: выразительная палитра, крупная типографика, пружинные переходы
- **Динамическая тема из обложки** играющего трека (или акцентный цвет на выбор)
- Адаптивная раскладка: боковая навигация на широких экранах, нижняя — на узких
- Полноэкранный плеер с двумя раскладками (стек, раздельная)
- **Синхронизированный текст песни** с автопрокруткой и подсветкой строки
- **Масштаб интерфейса**: автоопределение DPI окружения либо ручной выбор

**Аккаунт**
- Вход через Google (OAuth Device Flow) с автообновлением токена
- Либо вход по cookie браузера (SAPISIDHASH)
- Свои плейлисты, лайки, исполнители и подписки

**Доступ к сети**
- **Обход блокировок провайдера**: подмена хоста (domain fronting), прокси
  SOCKS5/HTTP, фрагментация TLS
- Проверка соединения прямо в настройках: показывает, что доступно, а что нет
- Автовключение обхода при первом запуске, если провайдер блокирует домен
- Кэш скачанных треков — при обходе звук играет из него

    auth/                       OAuth Device Flow, SAPISIDHASH, хранилище сессии
    innertube/                  клиент внутреннего API YouTube Music + обход ответов
    theme/                      Material 3 Expressive: схемы, формы, motion
    utils/                      форматирование длительности и чисел
  data/

  features/
    home/ explore/ search/ library/ album/ artist/ playlist/

## Почему такие решения

| Вопрос | Решение | Причина |
|---|---|---|
| UI-фреймворк | Flutter | Material 3 Expressive поддерживается фреймворком, а не собирается вручную |
| Внутренний API | собственный InnerTube-клиент | один код-путь для гостевого и авторизованного доступа |
| Ссылки на поток | `youtube_explode_dart` | чистый Dart, без внешних бинарников вроде `yt-dlp` |
| Аудио | `audioplayers` | работает на всех платформах без системных зависимостей; на Linux — GStreamer |
| Состояние | Riverpod | кэш, состояния загрузки и ошибок из коробки |

Аудиодвижок спрятан за интерфейсом `AudioEngine`. Если понадобится gapless
и точный seek, реализация на `media_kit` подставляется в `lib/core/audio/`
без изменений в интерфейсе.

## Сборка

Нужен Flutter 3.47+ (stable) и Dart 3.13+.

```bash
flutter pub get
flutter run -d linux      # или -d windows / -d macos / -d android
flutter build linux --release
```

### Зависимости для Linux

Приложение использует GStreamer (для `audioplayers`) и GTK3.
Проверить наличие:

```bash
pkg-config --exists gtk+-3.0 gstreamer-1.0 && echo OK
```

GStreamer должен уметь Opus и Matroska:

```bash
gst-inspect-1.0 opus matroskademux souphttpsrc
```

## Вход в аккаунт

Google не выдаёт сторонним приложениям общие OAuth-ключи, поэтому есть два пути.

**OAuth (рекомендуется).** Создайте бесплатный OAuth-клиент:

1. `console.cloud.google.com` → новый проект
2. Включите **YouTube Data API v3**
3. OAuth consent screen → добавьте себя тестовым пользователем
4. Учётные данные → OAuth client ID → тип **TVs and Limited Input devices**
5. Вставьте `client_id` и `client_secret` в приложении

**Cookie.** Откройте `music.youtube.com`, скопируйте cookie `SAPISID`
(или `__Secure-3PAPISID`) и вставьте в приложении. Быстрее, но токен живёт меньше.

## Масштаб интерфейса (HiDPI)

Flutter на Linux работает через GTK3, а тот поддерживает только **целочисленный**
масштаб. Дробные значения (GNOME 125%, 150%) разные оконные системы обрабатывают
по-разному, поэтому приложение само определяет масштаб и компенсирует его.

Правило компенсации (см. `lib/state/ui_scale.dart`):

- **DPR движка меньше системного масштаба** — масштаб до приложения не дошёл
  (типично для GTK3 и дробных значений: 125% → DPR 1). Интерфейс увеличивается
  до системного значения. Это классический случай «мелкого» приложения.
- **DPR равен или больше системного** — оконная система уже масштабирует сама.
  Например, Mutter при 125% отдаёт DPR 2 и сам понижает кадр до 1.25.
  Вмешиваться нельзя: интерфейс стал бы в 1.6 раза мельче.
- **Автоматическое уменьшение не применяется никогда.**

Управление:

| Способ | Как |
|---|---|
| Настройки | Внешний вид → **Масштаб интерфейса** (Авто / 50–200%) |
| Клавиатура | `Ctrl +`, `Ctrl -`, `Ctrl 0` (авто) |
| Разово | `MOPS_UI_SCALE=1.25 ./build/linux/x64/release/bundle/mops` |

Поддерживаемые источники системного масштаба: `GDK_SCALE`, `GDK_DPI_SCALE`,
`QT_SCALE_FACTOR`, `QT_SCREEN_SCALE_FACTORS`, `~/.config/monitors.xml` (GNOME),
`~/.config/kdeglobals` (KDE). Из нескольких источников берётся максимум, а не
произведение: они описывают одно и то же разными способами.

Диагностика: debug-сборка при старте печатает строку `[DPI]` с системным
масштабом, DPR движка, размерами окна и итоговой компенсацией.

```bash
flutter run -d linux 2>&1 | grep '\[DPI\]'
# [DPI] система: ×1.25 (GNOME, масштаб монитора (1.25)); DPR движка: 2.0;
#       физический размер: 2560×1440; логический размер: 1280×720;
#       компенсация: ×1.000
```

## Обход блокировок провайдера

Провайдер может обрывать соединение с YouTube по имени домена в TLS
рукопожатии (SNI). TCP при этом работает: рукопожатие к тому же IP с другим
именем проходит, а с `youtube.com` — нет. Диагностировать можно так:

```bash
# TCP проходит, а TLS — нет => блокировка по SNI
curl -s -o /dev/null -w '%{http_code}\n' https://music.youtube.com/     # 000
curl -s -o /dev/null -w '%{http_code}\n' https://www.google.com/        # 200
```

В приложении два механизма, которые включаются независимо.

### Подмена хоста (domain fronting)

Соединение идёт на разрешённый узел Google, а настоящее имя передаётся
в заголовке `Host`. Google обслуживает такой запрос как обычно. Побочный
бонус — обходится и фильтрация DNS: заблокированное имя вообще не нужно
разрешать.

| Что | Работает |
|---|---|
| Поиск, альбомы, исполнители, плейлисты | ✅ |
| Обложки, тексты песен | ✅ |
| **Аудиопоток** | ❌ |

Аудио так обойти нельзя: медиафайлы отдаёт отдельный сервер
(`*.googlevideo.com`), у которого собственный backend — через фронт-узел
Google запрос до него не доходит. Для звука нужен прокси или системный обход.

**Настраивать ничего не нужно.** Подмена хоста включена по умолчанию и
работает сразу: на незаблокированной сети она безвредна, а на заблокированной
без неё приложение не работает вовсе. При запуске приложение само проверяет
доступность и отключает подмену, только если она через этот узел не работает,
а прямой доступ есть.

### Прокси

SOCKS5 или HTTP-прокси. Даёт полную работоспособность, включая звук:
при включённом обходе аудио скачивает само приложение (где обход работает),
а затем проигрывает из кэша — GStreamer ходит в сеть напрямую и про обход
не знает.

### Фрагментация TLS

Первый пакет соединения дробится на мелкие части, чтобы имя домена не
попало в один сегмент. Помогает не везде: если оборудование провайдера
собирает TCP-поток обратно, приём не срабатывает. Проверено на живом
соединении: узел действительно дробит пакеты (есть тест), но конкретный DPI
их пересобирает. На сетях без пересборки фрагментация работает — поэтому
она оставлена как опция.

### Что выбрать

| Ситуация | Решение |
|---|---|
| Есть `zapret` / `GoodbyeDPI` / VPN | системный обход, в приложении ничего включать не нужно |
| Есть свой прокси | Прокси — заработает всё |
| Ничего нет | Подмена хоста: просмотр, поиск и тексты без ограничений, звук — нет |
